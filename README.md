# 로스트아크 공대 일정 조율 봇

공대원들이 스프레드시트에 매주 수기로 일정을 적던 방식을 줄이고, 디스코드에서 입력 · 매칭 · 알림까지 처리하는 것이 목표입니다.

## 1. 목표

- 공대원의 입력은 **한 번 등록 + 예외만 수정**으로 끝낸다.
- 레이드별로 **가능한 시간대와 남은 캐릭터를 자동으로 매칭**해 일정을 제안한다.
- 정해진 일정은 **당일 아침 요약, 시작 전 리마인더**로 자동 알림한다.
- 주간 리셋(수요일 06:00 KST)에 클리어 현황을 자동 초기화한다.
- 기존 스프레드시트는 **읽기용 뷰**로 유지할 수 있게 내보낸다.

## 2. 현재 문제

| 문제 | 원인 |
|---|---|
| 매주 일정을 새로 작성 | 반복되는 패턴도 매번 수기 입력 |
| 캐릭터 수가 사람마다 다름 | 누가 어떤 캐릭터로 어떤 레이드를 남겼는지 추적이 어려움 |
| 가능 시간이 사람마다 다름 | 겹치는 시간을 사람이 눈으로 찾아야 함 |
| 알림 없음 | 일정을 놓치거나 확인을 요청하는 메시지가 필요 |

## 3. 핵심 개념

- **공대원(Member)**: 디스코드 유저 1명.
- **캐릭터(Character)**: 공대원 소유. 직업, 아이템 레벨, 골드 획득 지정 여부를 가진다.
- **레이드(Raid)**: 이름, 난이도, 인원(4/8/16), 최소 아이템 레벨.
- **주간 클리어(Clear)**: 캐릭터가 이번 주에 해당 레이드를 깼는지 여부. 리셋 때 초기화.
- **가능 시간(Availability)**: 요일별 기본 패턴 + 특정 주/날짜의 예외.
- **일정(Session)**: 레이드 + 시작 시각 + 참가 캐릭터 목록.

## 4. 기능 요구사항

### 4.1 입력 (공대원)

| 명령어(안) | 설명 |
|---|---|
| `/캐릭터등록` | 캐릭터 이름, 직업, 아이템 레벨 등록 및 수정 |
| `/가능시간대` | 요일별 평소 가능 시간대를 한 번만 등록 (버튼/드롭다운 UI) |
| `/불가` | 특정 날짜나 시간대를 이번 주만 불가로 표시 (예외 처리) |
| `/클리어` | 캐릭터의 레이드 클리어 체크 (일정 종료 시 자동 반영도 지원) |
| `/내일정` | 내 이번 주 일정과 남은 레이드 확인 |
| `/공대일정` | 공대 전체 이번 주 일정 조회 (요일순, 참가자/캐릭터, 인원 현황 "6/8", 미클리어 요약, 미배정 공대원). 필터: `오늘`, `이번주`, `레이드:OO` |
| `/도움` | 명령어 목록과 사용법 안내 |

#### `/도움` 상세

- 명령어를 **역할별로 묶어** 보여준다: 처음 시작하기 / 일정 확인 / 입력·수정 / 공대장 전용.
- 각 명령어에 **한 줄 설명과 사용 예시**를 붙인다. (예: `/불가 날짜:10/3 시간:20~24`)
- 처음 쓰는 사람을 위한 **시작 순서 안내**를 맨 위에 둔다: ① `/캐릭터등록` → ② `/가능시간대` → ③ `/공대일정`으로 확인.
- 본인에게만 보이는 메시지(ephemeral)로 응답해서 채널이 지저분해지지 않게 한다.
- `/도움 명령어:불가`처럼 특정 명령어의 상세 설명도 볼 수 있게 한다.
- 명령어 목록은 코드의 명령어 정의에서 자동 생성해, 기능을 추가해도 도움말이 뒤처지지 않게 한다.
- 공대장 전용 명령어는 권한이 있는 사람에게만 표시한다.

#### 공대장 전용 명령어 (초안)

일정 확정/수정/취소, 매칭 제안 실행, 알림 채널 및 시각 설정.

### 4.2 매칭 (자동)

1. 레이드별 **필요 인원**을 확인한다.
2. 이번 주에 **아직 안 깬 캐릭터**와 **입장 가능한 아이템 레벨** 조건으로 후보를 뽑는다.
3. 시간대별로 **가능한 공대원 수**를 계산한다.
4. 필요 인원을 채울 수 있는 시간대를 점수순으로 **2~3개 제안**한다.
5. 공대장이 버튼으로 확정하면 일정이 저장된다.

제약 조건:
- 한 공대원은 같은 시간에 하나의 캐릭터만 참여할 수 있다.
- 같은 캐릭터는 같은 레이드를 주 1회만 클리어한다.
- 한 공대원의 여러 캐릭터를 서로 다른 시간대에 배치할 수 있다.

### 4.3 알림 (자동)

| 시점 | 내용 |
|---|---|
| 매일 아침 (시각 설정 가능) | 오늘의 레이드 일정 요약 |
| 시작 30분 전 (설정 가능) | 참가자 멘션 + 참가 캐릭터 안내 |
| 일정 변경/취소 | 변경 내용 즉시 공지 |
| 리셋 전날 | 아직 안 깬 레이드 남은 인원 요약 |

### 4.4 리셋

- 매주 수요일 06:00 KST에 클리어 현황을 초기화한다.
- 예외 불가 일정은 해당 주가 끝나면 자동으로 만료된다.

### 4.5 스프레드시트 연동 (선택)

- 확정 일정과 클리어 현황을 구글 시트에 자동으로 내보내 기존 방식과 병행할 수 있다.
- 입력의 원본(source of truth)은 봇 DB, 시트는 읽기용으로 둔다.

## 5. 데이터 구조 (초안)

```
members        (id, discord_id, display_name)
characters     (id, member_id, name, class, item_level, gold_earner)
raids          (id, name, difficulty, party_size, min_item_level)
clears         (character_id, raid_id, week_start, cleared_at)
availability   (member_id, weekday, start_time, end_time)          -- 기본 패턴
exceptions     (member_id, date, start_time, end_time, type)       -- 이번 주 예외
sessions       (id, raid_id, start_at, status, created_by)
session_slots  (session_id, character_id)
```

## 6. 기술 스택 (제안)

| 영역 | 선택 | 이유 |
|---|---|---|
| 봇 | Python + discord.py | 슬래시 명령어와 버튼 UI 지원 |
| DB | SQLite로 시작 | 서버 없이 시작 가능, 필요하면 PostgreSQL로 이전 |
| 스케줄러 | APScheduler | 일일 알림, 리셋, 리마인더 |
| 시트 연동 | gspread | 구글 시트 내보내기 |
| 호스팅 | 개인 PC로 시작 → 무료/저가 클라우드 | 안정화 후 이전 |

## 7. 단계별 구현 계획

**1단계 (MVP)**: 캐릭터 등록, 기본 가능 시간 등록, 수동 일정 등록, `/공대일정`, `/도움`, 일일 알림, 시작 전 리마인더

**1.5단계 (선택)**: `/공대일정` 고정 메시지 자동 갱신 ✅, 일정 카드의 참가/빠지기 버튼 ✅

**2단계**: 클리어 체크와 주간 리셋(일정 기반으로 자동), `/불가` 예외 처리 ✅, `/내일정` ✅. 리셋 전날 미클리어 요약 알림 ✅

**3단계**: 자동 매칭 제안, 공대장 확정 버튼

**4단계**: 구글 시트 내보내기 ✅, 통계 (이번 주 완료율, 누적 참가 일정) ✅

### 숙제 구간 · 고정 파티 · 서폿 편성 (공대 시트 방식)

- **숙제 구간**: 캐릭터마다 `1780+`, `1750+_3` 같은 구간이 있고 구간마다 주간 레이드(골드 3 + 골드X 1)가 정해집니다. 구간표는 `config.toml`의 `[[tiers]]`에 있습니다. 구간을 안 정하면 레벨에 맞는 기본 구간(⭐)을 쓰고, `/숙제구간`이나 시트로 바꿉니다.
- **더보기**: 레이드별 `more_cost`. `/캐릭터목록` 끝에 클골 합계, 더보기 전부 했을 때 비용, 남는 골드(거래/귀속)가 나옵니다. 귀속 골드가 있는 레이드는 귀속에서, 없으면 거래 가능 골드에서 빠집니다.
- **고정 파티**: `[일정]` 시트의 파티 번호 = 같이 도는 파티. 요일이 있는 줄은 **매주 리셋 때 일정이 자동 생성**되고(시각을 비우면 `default_start` 기본 시각), 요일·시각이 둘 다 빈 줄은 `/일정제안`에서 파티원 모두 되는 시간에 이어서 배치됩니다. `/파티목록`, `/파티일정생성`.
- **서폿 편성**: 4명 = 1파티, 파티마다 서폿 최대 1 · 딜러 최대 3. `/일정참가`(본인)는 규칙을 강제하고, 공대장 수동 배정·시트·고정 파티는 허용하되 `/공대일정`·고정 메시지에 "⚠️ 2파티 서폿 없음" 경고. 서폿 직업은 `config.toml`의 `support_classes`.
- **클리어 표시**: 끝난 일정은 `✅ ~~레이드~~`, 예정은 🗓️, 아직 안 잡힌 숙제는 `미정 N`.

| 시트 | 내용 |
|---|---|
| 공대원 | 이름 · 대표캐릭터 · 월~일 가능 시간 |
| 레이드 숙제 | 공대원별 캐릭터 · 숙제 구간(드롭다운) → 레이드/골드X/클골/더보기/더보기 후 **자동 계산** (1000줄까지) |
| 일정 | 고정 파티: 파티 번호 · 구간 · 레이드 · 요일 · 시각 · 캐릭터(같이 가는 캐릭터 이름들을 쉼표로) — 파티 번호별 색 자동 |
| 레이드 이름 | 드롭다운 원본 (레이드 · 입장 레벨 · 인원) |
| 계산용 (숨김) | 숙제 구간표 · 레이드별 골드/더보기 — 레이드 숙제 수식이 참조 |

### 골드 레이드 자동 추천

- **골드 획득 캐릭터**: 공대원(원정대)별 아이템 레벨 상위 6캐릭터 (게임 규칙과 동일, 자동)
- **캐릭터별 골드 레이드**: 입장 가능한 레이드마다 골드가 가장 많은 난이도를 고르고, 그중 골드 상위 3개
  - 골드가 같으면 거래 가능 골드가 많은 쪽 우선 (예: 벨가르딘 노말 > 지평의 성당 3단계)
- `/캐릭터목록`에 캐릭터별 추천 레이드와 주간 골드 예상치, `/공대일정`에 "골드 레이드 남은 캐릭터"가 나옵니다.
- 추천 밖의 레이드나 난이도로 참가하면 막지 않고 경고만 띄웁니다.

### 레이드 정보 최신화 (골드 조정·너프·신규 레이드)

레이드 값은 `config.toml`에 있고(기준일 `data_updated`), 패치 때 두 가지 방법으로 갱신합니다.

| 상황 | 방법 |
|---|---|
| 골드/입장 레벨/인원이 바뀜 | 디스코드에서 `/레이드 수정 레이드:세르카 노말 골드:30000` → 즉시 반영, DB에 저장. 되돌리기는 `/레이드 초기화` |
| 레이드 추가·삭제, 여러 개 한꺼번에 수정 | `config.toml` 수정 → `/레이드 새로고침` (재시작 불필요, 바뀐 항목을 보여 주고, 파일 오류 시 기존 설정 유지) |

`/레이드 수정` 값이 `config.toml`보다 우선합니다. `/레이드 목록`에서 ✏️ 표시로 구분됩니다.
레이드의 `key`는 저장된 일정이 참조하므로 한 번 정하면 바꾸지 마세요.

### 아이템 레벨 자동 갱신 (로스트아크 공식 API)

| 명령어 | 설명 |
|---|---|
| `/원정대연동 대표캐릭터:이름` | 원정대 전체를 불러와 입장 레벨(기본 1640) 이상 캐릭터를 한 번에 등록 |
| `/레벨갱신` | 내 원정대 레벨을 지금 바로 갱신. 공대장은 `전체:True`로 공대 전체 |
| `/원정대해제` | 자동 갱신 끄기 (캐릭터는 유지) |
| `/캐릭터등록 이름:OO` | 직업·레벨을 비우면 API로 조회 |

- 연동한 공대원은 `sync_interval_hours`(기본 6시간)마다 자동 갱신됩니다. 공대원 1명당 API 요청 1번이라 분당 100회 제한과 무관합니다.
- 새로 입장 레벨을 넘긴 캐릭터는 자동 추가됩니다 (`auto_add_new`).
- 레벨 변화로 **골드 레이드가 바뀐 경우에만** 알림 채널에 공지합니다.
- 점검(503)이나 키 오류면 그 회차를 건너뛰고 다음에 다시 시도합니다.
- 다른 공대원이 이미 등록한 캐릭터가 포함된 원정대는 연동을 거절합니다.
- API 키: [Lost Ark OpenAPI 개발자 포털](https://developer-lostark.game.onstove.com) 로그인 → CLIENTS에서 발급 → `.env`의 `LOSTARK_API_KEY`. 키가 없으면 이 기능만 꺼지고 나머지는 동작합니다.

### 엑셀 일괄 입력 + 자동 일정 제안 (공대장)

1. `/시트양식` → 예시 데이터(로디코 / 로워붕·로소서·로권왕)만 있는 양식을 받습니다. 지금 등록된 정보를 채워 받으려면 `/시트양식 현재정보:True`.
2. 채워서 `/시트가져오기 파일:`로 올립니다. 구글 시트는 "파일 → 다운로드 → .xlsx"로 받아서 올리면 됩니다.
3. 미리보기(인식 인원, 오류 목록)를 확인하고 **[적용]**을 누릅니다.
4. **[이번 주 일정 제안 받기]** 또는 `/일정제안`으로 제안을 받고, 제안별 **[확정]**을 누릅니다.

시트 구성은 위 **숙제 구간 · 고정 파티 · 서폿 편성** 절의 표를 참고하세요.

**자동 제안 방식:** 캐릭터별로 아직 안 잡힌 골드 레이드를 모아 이번 주 남은 시간에 배치합니다. 인원이 많은 레이드부터(8인 → 4인), 같은 인원이면 골드가 많은 순서입니다. 가능 인원이 가장 많은 시각을 고르고, 남은 레이드가 많은 공대원을 먼저 태웁니다. 공대원 1명은 같은 시간에 캐릭터 하나만 들어가고, 한 캐릭터가 같은 레이드를 주 2번 들어가지 않게 합니다. `최소인원`을 정원보다 작게 주면 빈자리가 있는 일정도 제안합니다. 확정할 때 규칙을 다시 검사하고, 확정된 일정은 알림 채널에 참가자 멘션과 함께 공지됩니다.

### 구글 시트 내보내기 (읽기용, 공대장)

`/시트내보내기` 또는 30분마다 자동으로 스프레드시트의 탭 3개를 통째로 새로 씁니다. 원본은 봇 DB라서 시트를 고쳐도 봇에는 반영되지 않습니다.

| 탭 | 내용 |
|---|---|
| 이번 주 일정 | 날짜 · 시각 · 레이드 · 인원 · 완료/예정 · 참가 캐릭터 |
| 클리어 현황 | 캐릭터별 골드 레이드 상태 (✅ 완료 / 🗓️ 예정 / ❔ 미정) |
| 통계 | 공대원별 이번 주 완료율, 누적 참가 일정 수 |

설정 (한 번만):
1. [Google Cloud Console](https://console.cloud.google.com)에서 프로젝트 생성 → **Google Sheets API**, **Google Drive API** 사용 설정
2. 서비스 계정 만들기 → 키 추가(JSON) → 파일을 프로젝트 밖이나 `data/` 에 보관 (`data/` 는 git 제외)
3. 빈 스프레드시트를 만들고 **서비스 계정 이메일(`...iam.gserviceaccount.com`)을 편집자로 공유**
4. `.env` 에 `GOOGLE_CREDENTIALS_FILE=키 파일 경로`, `GOOGLE_SHEET_ID=주소의 /d/ 와 /edit 사이 값` 입력 후 봇 재시작. 자동 내보내기를 끄려면 `GOOGLE_AUTO_EXPORT=0`

설정이 없으면 이 기능만 꺼지고 나머지는 그대로 동작합니다. 서버 1개(공대 1곳) 사용을 전제로 합니다.

### 실행 방법

1. [디스코드 개발자 포털](https://discord.com/developers/applications)에서 앱 생성 → Bot 탭에서 토큰 발급
2. OAuth2 → URL Generator에서 `bot`, `applications.commands` 스코프와 `View Channels`, `Send Messages`, `Embed Links`, `Read Message History`, `Pin Messages` 권한으로 초대 링크를 만들어 서버에 초대
3. 설치 및 실행:

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env   # DISCORD_TOKEN 입력, 개발 중엔 DEV_GUILD_ID도 입력
.venv\Scripts\python -m bot
```

4. 서버에서 `/봇설정 알림채널:#채널` 로 알림 채널 지정 (지정 전엔 알림이 가지 않음)

테스트: `.venv\Scripts\python -m unittest discover -s tests -t .`

## 8. 도입 전략

- 봇이 안정될 때까지 **기존 시트와 병행**한다.
- 입력은 디스코드 버튼이나 명령어 **한두 번으로 끝나게** 한다.
- 공대원이 쓰지 않으면 의미가 없으므로, 1단계 MVP를 먼저 써 보고 피드백을 받는다.
